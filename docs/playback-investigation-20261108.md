# macOS 偶發 404 與等待時間排查

依據本次提供的 `debug.log`（602 行）、`playback.log`（2760 行）、日誌開關及安全配置分析。播放日誌範圍為 2026-11-08 13:25:13–13:50:30 UTC，跨多個程序；舊記錄也包含其中，不能當作單次復現的故障率。

## 已確認的現象

- `debug.log` 的 404 來自首頁、分類、播放地址、帖子、排行榜等業務介面，正文為 nginx HTML 錯誤頁。全部業務請求經過 `/api/edge/request`；這與下載影片清單/分片是不同環節。
- 媒體代理完成的 10 次清單、78 次分片/金鑰請求都為 HTTP 200；未記錄媒體 404 或致命 HLS 錯誤。首頁和吃瓜詳情均有真實播放記錄。
- 9 次使用者定位全部有匹配的首幀恢復，未出現定位超時。耗時為 1518、2986、430、547、1118、818、2401、1953、1282 毫秒，包含 8 次點選、1 次拖動，中位數 1282 毫秒。
- 最慢一次定位：13:44:09.656 發起，約 3 毫秒後開始請求目標分片，下載 2603 毫秒，約 10 毫秒後完成入緩衝，2986 毫秒時收到首幀。剩餘等待主要發生在分片下載階段。
- 三次播放器從載入源到首個 `playing` 分別約 3.68、3.35、4.62 秒。這不包含獲取業務資料/播放地址的等待；吃瓜詳情還需要使用者點選播放，不能把進入詳情到播放器掛載的整個間隔視為 API 耗時。
- 64 個分片從 `hlsFragLoaded` 到 `hlsFragBuffered` 的中位數為 11 毫秒，最大 77 毫秒。該樣本沒有顯示分片入緩衝是主要瓶頸；它不等同於測量介面幀率。
- 圖片網路嘗試中位耗時約 1.55 秒，最長 3.63 秒。10 次圖片傳輸失敗隨後重試恢復，圖片代理最終返回 200；這批日誌沒有圖片 HTTP 404。
- 已觀察到切出首頁時暫停和停止載入；未發現 `active: false` 且 `paused: false` 的播放器快照。嚴格模式開啟和關閉時都有成功播放，未記錄安全拒絕事件。

## 當前不能確定的部分

舊版業務 API 失敗只有無時間戳的 `debug.log` 錯誤，沒有請求編號、線路和嘗試耗時。因此不能把這批 404 精確對應到某條線路、安全模式或一次點選，也不能僅憑 nginx HTML 判定是源站部署、CDN 路由、某個後端節點還是代理路徑的問題。`security.json` 僅表示匯出時的配置，不能代表全部歷史請求。

現有網路自檢/線路測速只檢查站點首頁，HTTP 200 不能證明業務閘道器正常。不能憑主頁可達就認定線路可用，也不能保證切換固定線路一定恢復。

## 本次客戶端修正

1. HTTP 404、不可重試的 4xx、許可權和安全拒絕直接結束；保留只讀請求對超時/暫時性狀態的有限重試，避免重複請求確定失敗的資源。
2. 首頁介面失敗後結束轉圈，提供明確重試；HTTP 錯誤提示保留狀態碼並隱藏閘道器 HTML。
3. 分類首次開啟才請求預覽；每個頻道和帖子獨立顯示結果、錯誤及重試，不再等所有頻道後再請求帖子、一起展示。
4. 相同開關下增加 `api.begin/end` 與 `line.changed`：記錄時間、程序、請求/嘗試編號、操作類別、主機名、HTTP/業務狀態、響應型別、閘道器類別和耗時，不記錄賬號、搜尋詞或響應正文。
5. 尚未到達首位元組/下載結束時，HLS 分片計時記錄 `null`，修正原日誌裡的負耗時。

持續 5xx/超時仍保留最多三次、每次 20 秒的策略；這些修正不能消除上游故障或保證真實 CDN 下載提速。媒體代理目前先接收完整分片再返回給 WebView，因此 HLS 的首位元組耗時包含 Rust 下載完整分片的等待，應結合 `network.end.headers_ms/elapsed_ms` 分析。

## 驗證與後續採集

`pnpm test:api-loading` 在無頭瀏覽器內注入 404/503/慢請求/空結果，驗證頁面狀態、各頻道獨立更新/重試、隱藏分類不預取；Rust 網路測試驗證重試策略。`pnpm test:playback --scenarios seek,legacy` 繼續驗證真實影片點選/拖動和分片計時。測試不訪問上游，不能替代 macOS WKWebView/真實 CDN 驗證。

實機使用新構建開啟診斷日誌、重新啟動應用，復現一次首頁失敗與一次成功播放，並手動重試失敗頻道；保留當前及輪轉日誌。新的 `api.end` 能直接顯示哪條線路、哪個業務操作、哪次嘗試返回 404/503，以及等待時間。要繼續最佳化傳輸，應先用新日誌區分閘道器耗時、分片響應頭等待與正文下載；本次不憑這些樣本調整安全策略或回退 hls.js。
